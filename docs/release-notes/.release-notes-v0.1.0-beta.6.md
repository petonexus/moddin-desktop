# v0.1.0-beta.6 — the installer finally contains the app, and the first release the updater can verify

**Read this first:** every earlier installer shipped with **no frontend inside it**. The app launched and showed a blank window. The cause was a missing Cargo feature (`custom-protocol` on `tauri`), so the bundled build looked for a dev server at `127.0.0.1:1420` instead of its own embedded files. This release fixes it, and a build gate now fails if the feature is ever dropped again.

> ⚠️ Still a **beta**. It runs real installs, real registry writes and real process kills. Read the [User Guide](https://github.com/petonexus/moddin-desktop/blob/main/docs/USER-GUIDE.md) before applying anything new.

---

## What changed

### The window is no longer blank

`tauri` is now built with `custom-protocol`, so the installer embeds `dist/` and loads it. `scripts/check-bundle-features.mjs` walks the repository for `Cargo.toml` files and fails CI when the feature is missing.

### The first updatable release

Releases now carry a signed updater payload (`-setup.exe`, its `.sig` minisign signature and a CI-generated `latest.json`). The updater public key is in `tauri.conf.json`; the build refuses to compile with the old placeholder. Older installs must download the installer manually. The in-app updater currently follows the stable channel; beta releases do not appear at its `/releases/latest` endpoint.

### Trust

The community signing key is pinned against a compiled keyring, the cached catalog is re-verified on every read, the YAML fetch host is allow-listed, and revocations now travel *inside* the signed `catalog.json`, so one signature covers both halves and they cannot disagree. Downloaded YAML must also match `yamlSha256` in that signed catalog; `SIGNED-BY` keys must belong to the compiled, non-revoked keyring. Unsigned consent cannot bypass the digest or downgrade an entry declared signed.

### Mods install what they advertise

The install transaction opens before the step loop, steps are confined to the install root, `extract-zip` can filter members with `include`/`exclude`, `%VAR%` is expanded in paths with a JSON-safe `write-text-file`, and an archive in which two members claim the same proxy name is refused.

### Smaller and stricter

The installer is about 23% smaller, the runtime is staged from a lockfile, and `cargo fmt` and `clippy` now block CI. Rust and frontend regression tests cover the safety and UI paths; validation results are recorded per build.

### Safer installation and release checks

Any failure while planning, extending backups, executing steps or committing an installation now attempts rollback. Recovery failures retain the original error and identify the transaction. Community, Collections and Contribute use the live library selection, AI receives catalog game IDs, and `kill-process` resolves the configured image name. Capability installs/removals enter activity history. Runtime debug overlays require development mode or explicit opt-in.

Release versions now agree across npm, Cargo and Tauri (`0.1.0-beta.6`). CI validates tag/version equality. The Release workflow supports manual artifact dry-runs without publishing.

### AI permissions and installed MCP

Headless AI requires confirmation before sending context to the provider. CLI
permission bypasses are removed; authoring uses restricted modes and can be
cancelled. Output streams are drained concurrently with bounded buffers and
Codex's last answer is read before cleaning the run directory. The installed MCP
ships its own catalog snapshot and no longer depends on a developer checkout.

### Interface

`App.vue` is split by responsibility, there is one dialog implementation and one error path, and the empty states, localization boundary and accessibility have had a pass.

---

## Known gaps

- **Catalog key migration:** this build pins the replacement signing key `bbe4bcb7ebd11a6f`. Older clients need a manual update to beta.6 before they can verify catalogs signed by that key. Community recipes retain their own availability status.
- The `ofxr-bridge`, `uevr` and `reframework` recipes are still `status: planned`. UE4SS is available; the installed game and required configuration must be resolved.
- The per-game OpenXR binding is not shipped: it depends on a decision about what Undo does with files outside the install root.

The full audit and reasoning are in [`docs/AUDIT-2026-09-29.md`](https://github.com/petonexus/moddin-desktop/blob/main/docs/AUDIT-2026-09-29.md) and `ROADMAP.md`.
