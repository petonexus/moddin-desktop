# v0.1.0-beta.5 — dependencies, build compatibility, and a real download step

Three features that Moddin already half-knew how to do finally reach the screen, plus a fix for installs that silently went nowhere. This is the beta where **mods can depend on other mods**, can refuse to install on an unsupported game build, and can tell you *whose* file they are about to replace.

> ⚠️ Still a **beta**. It runs real installs, real registry writes and real process kills. Read the [User Guide](https://github.com/petonexus/moddin-desktop/blob/main/docs/USER-GUIDE.md) before applying anything new.

---

## What changed

### Mods can have prerequisites

A recipe can now declare `dependencies:` and Moddin installs what is missing before the mod itself, in order, each with its own transaction. A Cheeky-on-UEVR plugin for a game that has neither UEVR nor OptiScaler gets both installed first, and the card tells you what came along.

Cycles, chains longer than 8, and ids that do not exist are refused with the whole chain spelled out, so a typo fails loudly instead of half-installing.

Game catalog entries can declare the same thing, and the library now offers you the prerequisites before applying the mod that needs them.

### Mods can check the game build

A recipe can pin the game versions it supports. Moddin reads the executable's `FileVersion` before installing and refuses when the build is outside the window, naming the file it probed.

The card explains the refusal and offers an explicit **install anyway**. If you take it, the warning stays on screen afterwards — an override you cannot see is an override you cannot undo.

### Proxy conflicts now name their owner

Installing OptiScaler over a `dxgi.dll` used to show a filename and nothing else. It now says whether the file is **installed by Moddin** or **from another mod**, and replacing a third-party file takes an explicit tick that re-runs the preview. The chosen resolution is pinned to the request, so a preview that went stale is refused instead of overwriting whatever took the slot in the meantime.

### Fixed: community and AI installs went nowhere

Installing a community mod, or accepting an AI recommendation, sent **empty install and executable paths** to the backend. Recipes that extract archives and write files resolved those against Moddin's working directory: the install reported success, wrote nothing into the game, and recorded no transaction to undo.

Both surfaces now resolve the selected game properly — the same folders the per-game cards use. If no supported game is selected, the install is refused with a message instead of pretending.

### New: mods can download their own files

Until now **no install step could download anything** — the extract step read a local path, so every recipe that pointed it at a URL failed with a file-not-found. A new `download-file` step fetches over HTTPS with a host allow-list, a size cap and SHA-256 verification, and stores the archive in Moddin's own cache so it never lands in your game folder.

### BepInEx, UE4SS and REFramework are recipes now

BepInEx used to be a Rust command that nothing in the UI could reach. It is a capability recipe now — download, verify, extract — and rolls back cleanly, restoring the game folder instead of deleting two files and leaving a folder behind. UE4SS and REFramework are declared as planned recipes that say plainly they are not installable yet, replacing Rust stubs that returned "not implemented" for every operation.

Installers, catalogue entries and dedicated Rust commands for those three were removed. If your BepInEx recipe relied on automatic Unity x86/x64 detection, note that the release URL is now pinned per game in the recipe rather than sniffed at install time.

### Smaller fixes

- `status: planned` is now enforced. A planned recipe used to "install" successfully, write nothing, and record no transaction.
- The `mod-loader-plugin` agent template and the other three templates pointed the extract step at a URL; they now download first.
- The agent's step and check catalogues learned the new step kind.

## Install (Windows 10 / 11 x64)

Download the installer below and run it. It puts Moddin in `%LOCALAPPDATA%\Programs\Moddin Desktop` and adds an uninstaller to **Settings → Apps**.

- **Installer:** `Moddin.Desktop_0.1.0_x64-setup.exe` (attached below) — NSIS, installs per-user, no admin required
- **SHA-256:** `1B33389D253DD3A2967977573F87D2D1F32E3208595852CD4D7CF5D97B6F35CF`
- The installer is larger than beta.4 (3.8 MB) because it now ships the Node runtime and the AI agent alongside the app, which is what lets the local-AI features run offline.
- WebView2 Runtime is required (pre-installed on Windows 11; Windows 10 installs it automatically if missing).

If you already installed beta.4, you can install this on top — it replaces the same files.

> **The installer was replaced after the first upload.** The first build shipped a broken **Fazer com Codex** button: Moddin passed the headless flags to the bare `codex` command, and current Codex (0.158.x) only accepts them on its `exec` subcommand, so the run died with `unexpected argument '--skip-git-repo-check' found`. Re-download the installer — the **SHA-256 above is the fixed build**; anything with a different digest is the broken one. Claude Code and Cursor were never affected.

## What to test

- [ ] Open the **AI mods** section for a game and confirm it loads (it now also lists the shipped recipes, not only the ones you created)
- [ ] Save a mod that declares `dependencies:` and install it on a game where the prerequisite is missing — both should install, and the card should name what came along
- [ ] Write a recipe with a `compatibility:` block and a build that does not match: Apply should be disabled with the reason, and **install anyway** should work and leave a visible warning
- [ ] Install OptiScaler on a game folder where another mod owns `dxgi.dll`: the conflict list should name the owner and offer the replace tick
- [ ] Install a community mod from the community panel and confirm it actually writes files into the game folder, and that the change shows in History
- [ ] Click **Fazer com Codex** in this dialog with a current Codex CLI installed and confirm it returns a real answer instead of an argument error
- [ ] Confirm a planned recipe (UE4SS, REFramework) refuses to install with a clear message

---

## Known gaps in this beta

- The shipped OptiScaler, ReShade, UEVR, OFXR Bridge and Cheeky recipes still pass a URL where a local path is expected. They are not reachable from the library (their own installers handle those modules), and they are being rewritten in a later beta.
- Installing a community mod or an AI recommendation still needs a supported game selected in the library first.
