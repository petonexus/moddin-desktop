## Summary

This PR adds **`moddin-agent/`** — an MCP server + agent skill that lets an AI assistant add new mods to Moddin Desktop by authoring capability recipes the user then previews and applies inside the app — and ships the rest of the working copy alongside it.

The user talks to their AI assistant in natural language (*"add this FPS unlocker to Elden Ring"*); the agent asks the few questions it can't guess, drafts a capability YAML, validates it against the JSON Schema mirror of the Rust `CapabilitySpec`, shows the predicted diff, asks for explicit confirmation, and writes the file to `%LOCALAPPDATA%\Moddin\capabilities\`. The user opens Moddin, clicks **Rescan**, the new capability appears, and the normal preview / transaction / rollback pipeline takes over.

## Highlights — `moddin-agent/` (new)

- **`src/mcp-server.mjs`** — single-file Node.js MCP server over stdio. **11 tools**:
  - `moddin_status`, `list_supported_games`, `get_game_info`
  - `list_capabilities`, `get_capability`
  - `get_step_kinds`, `get_check_kinds`
  - `get_capability_template`
  - `validate_capability_yaml`
  - `preview_capability_plan`
  - `save_capability_yaml`
- **`schema/capability.schema.json`** — JSON Schema mirror of `src-tauri/src/capability.rs`. Source of truth for `validate_capability_yaml`.
- **`templates/`** — starter recipes for four patterns: `extract-zip`, `proxy-dll`, `registry-override`, `vr-runtime-overlay`.
- **`SKILL.md`** — system prompt the agent loads alongside the MCP server. Walks it through the workflow (intent → template → compose → validate → preview → confirm → save).
- **`scripts/validate-templates.mjs`** + **`scripts/smoke-test.mjs`** — CI guards. Both wired into `.github/workflows/ci.yml`.
- **`README.md`** — install + how to register the MCP server with Claude Desktop / Claude Code / Codex / Cursor.

## Hard safety boundaries (the non-obvious bit)

The agent **cannot** invoke install / uninstall / rollback. The MCP server has no such tool. The only filesystem write is `save_capability_yaml`, which is restricted to `%LOCALAPPDATA%\Moddin\capabilities\` (the same folder Moddin Desktop already reads). Every save is schema-validated first. Moddin stays the source of truth for every destructive action — the agent is purely an authoring assistant. Full threat model in `docs/AGENT-RECIPES.md`.

- **Frontend** — `services/catalog.ts`, `services/pcgw.ts`, `services/profile.ts` plus the matching `types/*` mirror the new Rust commands.
- **Community catalog** — `catalog.json` (initial snapshot), `moddin-community-capabilities/` as a proper submodule pointing at `petonexus/moddin-community-capabilities.git` (with `.gitmodules`).

## Post-merge checklist

```powershell
npm ci
cd moddin-agent && npm ci && node scripts/validate-templates.mjs && node scripts/smoke-test.mjs
cargo test --manifest-path src-tauri/Cargo.toml
```

To register the MCP server with an agent (Claude Desktop / Claude Code / Codex / Cursor), add to its `mcpServers`:

```jsonc
{
  "mcpServers": {
    "moddin": {
      "command": "node",
      "args": ["<repo>/moddin-agent/src/mcp-server.mjs"],
      "env": { "MODDIN_PROJECT_ROOT": "<repo>" }
    }
  }
}
```

Then load `moddin-agent/SKILL.md` as a skill in the agent and you're done.
